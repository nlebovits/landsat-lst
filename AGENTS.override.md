# Repository agent instructions

The untracked `AGENTS.md` in this repository is generated by `claude-mem`. Read it
when present for supplemental history, but follow this tracked file for durable
repository rules.

## Performance and cost work: the smoke test comes first, in the conversation

Read the section of that name at the top of `CLAUDE.md` and follow its order.
Before a plan, an estimate, an analysis, a subagent, or a line of code: one
paragraph in the conversation naming the measured number your idea moves, the
buried idea you are not repeating, and what would make it worthless; then the
bare-minimum Coiled smoke test that would kill it, bounded under a dollar and
30 minutes, and wait for the operator's go; then that one run and its actual
numbers from `landsat-lst evidence collect`; and only then any architecture or
review. If you cannot write the paragraph, say so and stop.

## Mandatory performance-evidence gate

Read and follow `docs/performance-evidence-policy.md` before investigating,
implementing, reviewing, or reporting work involving runtime, throughput, memory,
I/O, concurrency, scaling, cloud cost, or resource efficiency.

Do not begin production optimization, broad correctness hardening, or an
implementation-focused adversarial review from a plausible mechanism, synthetic
result, local microbenchmark, model, estimate, or user-reported number. Those
inputs may justify only a pre-registered bounded discriminator and its smallest
reversible experimental treatment. Add no broader implementation before running
the cheapest representative real-data discriminator in the target environment.

An optimization may proceed only when a validated evidence bundle records
`decision: proceed`. If it records `decision: stop`, or the required evidence
does not exist, stop optimization work and report that outcome. Never fill an
evidence field from memory or inference, relabel modeled or user-reported values
as measured, omit contrary runs, or describe unit tests as performance evidence.

Every PR must retain the `performance-evidence` declaration from the pull request
template. Cloud contracts constrain experiments but never authorize spending;
obtain explicit operator approval for every launch.

## Prose written by agents

Read `docs/PROSE.md` before drafting or editing Markdown. Apply its voice rules
to generated text before committing it: remove chatbot residue, unsupported
hype, repetitive list cadence, and stock transitions. State causal or
conditional relationships directly. Avoid formulaic resultative frames and
affirmative-negative sentence pairs.

Run the error-level gate with `uv run prek run vale --all-files`. Run the full
Vale and proselint audits with the manual commands in `docs/PROSE.md`; treat
their warnings as prompts for editorial judgment, not mechanical rewrites.
